A Claude Code Stop hook, powered by Kane CLI

Your agent says done. Kane checks first.

kane-gate won't let your AI coding agent end its turn until Kane CLI has clicked through the change in a real browser. If a check fails, the agent gets Kane's findings and keeps working.

npx kane-gate init

Works with any web app. Needs Kane CLI and Claude Code.

    What the agent reads when the gate stays shut

    The Stop hook answers Claude Code with {"decision":"block"} and a reason. That reason is written for a model to act on, built from Kane's own run:

    • Expected vs. observed for every failed check, so the agent fixes the cause instead of guessing.
    • The failed step and the evidence pack, so you can replay exactly what Kane saw.
    • A standing rule: fix the application, not the spec. Kane's own summary sometimes suggests changing the test; the agent is told to ignore that.

    How the gate decides

    Every time Claude tries to end a turn, Claude Code runs the Stop hook. kane-gate then takes these steps, in order.

    1. Skip what's already proven

      If the working tree hasn't changed since the last green run, the agent may stop at once. No credits spent.

    2. Make sure the app is up

      kane-gate checks baseUrl and runs your startCommand if nothing answers, then waits up to 60 seconds.

    3. Run every spec through Kane

      kane-cli run --agent per spec, in a real Chrome. kane-gate reads Kane's NDJSON stream as it goes.

    4. Open, or send it back

      all pass the turn ends and you see ✓ 2/2 specs verified.

      any fail the stop is blocked and Kane's findings become the agent's next instruction. After three rounds it stops and tells you what is still red.

    Safe to leave on

    A gate you switch off after a day is no gate. These are the parts that make it livable.

    Flaky browser, not a bug
    Tooling errors such as TargetClosedError are retried once and never reported to the agent as app failures. We hit this on day one.
    Specs can't be quietly weakened
    kane-gate remembers each spec when it first fails. If the agent edits one mid-fix, the next message says so.
    Credits stay predictable
    One Kane run costs about 12–25 credits here. An unchanged tree is never re-verified, and specs run one at a time.
    Never wedges your session
    If kane-gate itself crashes, the hook exits cleanly and the agent can stop. You keep control.

      npm install -g @testmuai/kane-cli

      kane-cli login

      npx kane-gate init

      npx kane-gate watch
